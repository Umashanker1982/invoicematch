# Phase 5: Adoption and change management

A technically correct system that nobody uses is a failed engagement. This plan turns the people risks found in discovery (fear of replacement, fear of blame, need for control) into concrete actions.

| Document | What it covers |
|---|---|
| [training_plan.md](training_plan.md) | Training for procurement, AP, approvers, compliance, audit, and security, structured with Prosci ADKAR |
| [pilot_rollout.md](pilot_rollout.md) | Shadow mode → pilot wave 1 → wave 2 → full rollout, with gates and rollback criteria |
| [executive_communication.md](executive_communication.md) | Who hears what and when, the metrics dashboard, and the weekly one-page update template |
| [feedback_loop.md](feedback_loop.md) | How overrides, flags, and auditor disagreements become test cases and safe releases |
| [demo_script.md](demo_script.md) | Minute-by-minute script for the final stakeholder review, using the live demo, with likely questions |

**In one line:** prove it in shadow mode, expand only on evidence, keep people in charge, and make every correction a permanent test.
